# LLMコード生成によるロボットアーム制御実験

マルチモーダルLLMを「ロボットの制御器」ではなく「ロボットのプログラマ」として使う実験です。作業内容の変化（障害物の追加）を人間がテキストで伝え、LLM（Claude）が制御コードを書きます。コードは実行前に検証し、通ったものだけをシミュレータ（MuJoCo）で実行します。

拡散モデルのAction Headが「環境を条件に行動を生成する」のに対して、この方式は「環境を条件にプログラムを生成する」ものです。この対比を、小さなプロトタイプで確かめることが目的です。

## しくみ

```
人間の指示（数値／あいまい）
  → LLMが plan(target, obstacles) を書く（関節角の経由点を返す関数）
  → サンドボックスで実行して経由点を得る（import は math だけ、10秒で打ち切り）
  → 検証：可動範囲、障害物との接触（安全余裕 2 cm）、最終誤差 1 cm 以内
      不合格なら理由を返して書き直し（最大3回）
  → MuJoCoで実行し、物理的な接触と最終誤差を記録
```

- ロボット：水平面で動く2関節アーム（リンク長 0.5 m と 0.4 m）
- シナリオ：5つ（S1：対照、S2：肘の向きを変える、S3〜S5：腕を折りたたんで回り込む）
- 条件：生成方式（ゼロから生成／既存コードの差分修正）× 指示（数値／あいまい）
- 試行：4条件 × 5シナリオ × 3回 ＝ 60試行

## 環境

- Mac mini M6（Apple Silicon）、Python 3.12（Homebrew）、JupyterLab
- MuJoCo、mediapy、Pillow、pandas、Anthropic Python SDK
- LLM：claude-sonnet-5-5

```bash
cd llm_arm
python3.12 -m venv .venv && source .venv/bin/activate
pip install mujoco mediapy anthropic jupyterlab pandas pillow
echo 'ANTHROPIC_API_KEY=sk-ant-...' > .env && chmod 600 .env
jupyter lab
```

`llm_arm_mac.ipynb` を開き、上の節から順に実行します。§10まではAPIを使わずに動作を確かめられます（ダミーのLLM）。3Dビューアは `mjpython view_run.py --scene S3` や `mjpython view_run.py S3_scratch_numeric_t1 1` で開きます。

## 結果（2026年10月28日）

全60試行が、3回までの書き直しで検証に合格しました。

| | 1回目で合格（S3〜S5） | 1回目の主な失敗 |
| --- | --- | --- |
| ゼロから生成 | 18試行中15 | importの違反、途中切れ（各1〜2件） |
| 差分修正 | 18試行中1 | 出力の上限（8,000トークン）での途中切れ |

## わかったこと

1. **障害物にぶつかる計画は、84回の生成で0件。** LLMは毎回、自分で衝突判定と経路探索（関節空間の格子探索など）を書き、検証関数の刻みを見越して判定を少し厳しめにしていた。今回のシナリオは、仕様を渡せば1回で解ける難しさだった
2. **検証→書き直しのループが効いたのは、形式の誤りだけ。** 途中切れやimportの違反は理由を返すと直ったが、幾何的な誤りを直す場面は現れなかった
3. **差分修正では、1回目の失敗21件がすべて途中切れ。** 合格したコードの行数は方式でほぼ同じ（平均142行と131行）で、途中で切れた返答の多くは文字数が短い（0文字のものもある）。既存コードを渡されると、出力の前の推論（thinking）が長くなり、上限に達したとみられる（推論の中身は未記録のため推定）
4. **あいまいな指示でも、成功率は下がらなかった**

## 限界と今後

- シナリオが易しすぎた。障害物を複数にする、狭い隙間を通らせるなど、幾何の誤りが出る条件で検証のループの効果を確かめたい
- 推論の長さを記録し、推論に使う量を指定して、差分修正での途中切れの原因を確かめたい
- 検証関数をツールとしてLLMに渡す条件（ループをLLMの内側に置く）と比較したい
- 費用：修正後の84回の呼び出しで約5.3ドル（入力 約19万、出力 約49万トークン）。出力の多くは推論とみられる
